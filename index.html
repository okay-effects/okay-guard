See and control what an AI agent does

An agent works through MCP servers — payments, mail, files, code. okay-guard stands between them: every call is seen, your rules decide what passes, what is blocked and what waits for you — and you decide on your phone, where the call stands.

Connect your agent — the studio, here, for anyone: give your agent (Claude Code, Claude.ai, Cursor) the MCP address it shows, add the remote MCP servers it should use, try the prompt it suggests, watch every call meet your policy. Nothing to install, no key, no account; everything kept in your browser, servers called straight from it.

Or run it on your machine — the same studio from okay-guard.zip (Node) or okay-guard.jar (Java): any server, the policy you made here taken along with a copy.

Or watch a scripted agent in the browser

What it does

  • Every call, seen. The run reads like a conversation: the task, what the model says, each tool's call with its arguments, what the rules decided, what came back, how long it took. Secrets are masked before anything is recorded.
  • Rules, in words. Ask for create_refund when amount > 20000. Block delete_*. The first that matches decides — pass, ask, block — made from what happened, one tap on a call.
  • You decide. A call that waits is a card where it stands: approve it, refuse it with a reason the agent is told, or change its arguments first. No answer in time: the agent is told it is not done.
  • Agents, made and tested. An agent is data — a model, its instructions, its servers, its rules. A test is a task, what a person says, tools stubbed, checks on what happened; its model's replies kept and replayed, so a change of the rules is tried against what the agent did — with no model and no key. Headless, for CI.

On your machine

Node 18+: download okay-guard.zip and unzip it. Or Java 17+: download okay-guard.jar, one file, the page inside. The same program on both; open the studio — the same as here, its page at 127.0.0.1 with a token of its own:

node okay-guard.js --open                 # the studio: agents, servers, rules, policies, tests
java -jar okay-guard.jar --open           # the same, on the JVM
node okay-guard.js test                   # every test, headless: exit 1 if one fails
node okay-guard.js check policy.json      # a policy checked by its cases, no model, no server

Made and tried here first? Agent → Export a copy on the site, Import a copy on your machine: the agent, its servers, its rules and its policy come along. Your agent then connects to the address the machine's studio shows (http://127.0.0.1:…/m/…/mcp), and every server is reachable — those a browser may not call too.

Or put the guard where a server's command was — in Claude Code, Claude Desktop, any MCP client over stdio:

{ "mcpServers": { "stripe": { "command": "node",
    "args": ["/path/to/okay-guard.js", "--rules", "/path/to/policy.json", "--open",
             "--", "npx", "-y", "@stripe/mcp", "--api-key=${STRIPE_KEY}"] } } }

On the JVM: "command": "java", "args": ["-jar", "/path/to/okay-guard.jar", …].

--lan offers the page to your phone on the same Wi-Fi.

In the cloud

Nothing installed, nothing kept in the cloud: open the studio, give your agent — Claude Code, Claude.ai's connectors, Cursor — the MCP address it shows, and watch and decide in the page, on your phone too. Your agents, rules and policies stay in your browser; the Worker only passes messages, and only while the page is open.

How it is made

Scala 3 and Scala.js, on algebraic effects: the guard is a program over its own effects — the wire, the journal, the rules, a person, the clock — and every place it runs (Node, a Durable Object, this very page in the demo) is only their handlers. A call waiting for you is the program's continuation, kept until you answer.
