The policy language

A policy says what an AI agent may do with its MCP servers: what goes ahead, what waits for a person, and what is never done. okay-guard checks every call against it before the call reaches the server.

The language is small. It has declarations of what can be known, and rules about what is allowed. It is typed: a misspelt argument or a comparison of a text with a number is an error in the editor, before anything runs. Every decision is a theorem with a certificate, so the journal shows exactly why a call was allowed or denied, and anyone can check that again.

All the examples on this page are real files, checked by okay-guard with their tests: policy-examples/.

A first policy

An agent handles refunds. It may look at charges and make small refunds. A person decides on a big refund. It never deletes a customer.

first.policypolicy refunds

type User

call list_charges()
call create_refund(charge: Text, amount: Int)
call delete_customer(customer: Text)

allow list_charges

allow create_refund
  when amount <= 20000

ask create_refund
  when amount <= 100000
  because "more than 200 €: you decide"

deny delete_customer
  because "nothing is deleted from here"
  • policy refunds names the policy.
  • type User declares who calls. Every rule may use caller, the agent that calls, as a User.
  • call declares a tool of the MCP server and the types of its arguments. A rule may only use the arguments its tool has.
  • allow, ask, deny are the rules. when is the condition; because is the reason the agent and the person are told.

Where to write it:

  • In the studio: Rules shows the policy, and Make a rule on any call adds a rule from that call. The studio checks the text as you type, runs its tests, and decides your agent's calls by it.
  • In a file: refunds.policy, with its tests in refunds.tests beside it. okay-guard check refunds.policy runs the tests, and okay-guard --rules refunds.policy -- <server> runs an agent under it.

How a call is decided

For each call, okay-guard takes the rules whose target matches the call, and checks their conditions. Then:

  1. If a deny applies, the call is denied.
  2. Otherwise, if an allow applies, the call is allowed.
  3. Otherwise, if an ask applies, a person is asked.
  4. Otherwise the call is denied: nothing is allowed without a rule that allows it.

The order of the rules in the text does not matter. A deny always wins, so a later allow cannot open what a deny closed. A rule with no when always applies.

Watch out: an allow beats an ask. With allow create_refund and no condition, an ask create_refund never asks. Give the allow the condition under which no person is needed, as amount <= 20000 above.

Targets: a tool, a server, every call

A rule's target is one tool (create_refund), every tool of a server (github.*), or every call (*). A tool written with its server's name, github.get_file, is that server's tool only: the same policy can hold rules for several servers, and each rule decides the calls to its own server.

servers.policypolicy servers

type User

call github.get_file(repo: Text, path: Text)
call github.create_pull_request(repo: Text, title: Text)
call github.delete_repo(repo: Text)
call fs.read(path: Text)
call fs.write(path: Text)

allow github.get_file
  when repo starts "my-org/"

ask github.create_pull_request
  because "a pull request: you decide"

deny github.delete_repo
  because "never"

allow fs.read
allow fs.write
  when path starts "/workspace/" and not (path ends ".env")

Allow everything, deny some

The default is to deny. To allow everything except a few things, allow * and deny the rest. A deny still wins.

everything.policypolicy everything

type User

call read_file(path: Text)
call delete_file(path: Text)

allow *

deny delete_file
  because "nothing is deleted"

Writing rules

Types

Intwhole numbers, of any size: amounts in cents, counts
Decexact decimals, for money: 500.00. Int and Dec are not mixed silently: dec(count) converts.
Texttext: "eur"
Booltrue or false, for arguments and fields: a condition by itself (dry_run, not force)
User, Account…an entity type the policy declares (type Account); its values are names
type Item = { sku: Text, qty: Int }a record, for an argument that is a JSON object; note?: Text is an optional field
List[Item]a list, for an argument that is a JSON array

An optional argument is declared with ?: coupon?: Text.

Conditions

amount <= 20000comparisons: = != < <= > >=
a and b, a or b, not a, ( … )combining conditions
currency in ["eur", "usd"]one of a list
path starts "/workspace/"texts: starts, ends, contains
amount + fee <= 100, amount * 1.2sums and differences; a product by a number only
has(coupon)an optional argument or field is there
shipping.countrya record's field
count(items) <= 20a list's length
every i in items: (i.qty <= 10), some t in tags: (t = "test") each element of a list, or one of them

An argument that is missing makes the condition that uses it fail, so a rule that needs it does not apply. A missing argument can therefore deny or ask, but it never allows. Ask has(…) first to decide on its absence.

shop.policypolicy shop

type User
type Item = { sku: Text, qty: Int, price: Dec, note?: Text }
type Address = { country: Text, zip?: Text }

call shop.order(items: List[Item], shipping: Address, coupon?: Text, dry_run: Bool)

allow shop.order
  when dry_run

allow shop.order
  when count(items) <= 20
   and every i in items: (i.qty <= 10 and i.price <= 500.00)
   and shipping.country in ["DE", "PL"]
   and (not has(coupon) or coupon starts "VIP")

Reasons

because "…" gives the reason. The agent is told it when a call is denied, and the person reads it on the card when a call waits. The journal records it with the rule and the values the rule met.

Comments

-- starts a comment, to the end of the line.

Facts and state

State: what the guard remembers

A state is a value okay-guard keeps between calls: a sum, a count. It can be kept per minute, hour or day; after the window, it starts again from its initial value. A rule changes it with then, only when the call goes ahead: when it is allowed, or asked and then approved. A count rule decides nothing; it only changes state for every call that goes ahead.

budget.policypolicy budget

type User

state refunded(user: User): Int per day = 0
state calls(user: User): Int per minute = 0

call create_refund(charge: Text, amount: Int)
call list_charges()

deny *
  when calls(caller) >= 30
  because "too many calls: wait a minute"

allow list_charges

allow create_refund
  when amount > 0 and refunded(caller) + amount <= 20000
  then refunded(caller) += amount

ask create_refund
  when amount > 0 and amount <= 100000
  because "over 200 € refunded today: you decide"

count * then calls(caller) += 1

Facts from the servers

A fact is something the policy needs to know that is not in the call. from mcp makes okay-guard ask a tool of the agent's server itself, before it decides. The agent does not see this call, and the policy does not decide it. at "…" is the path to the value in the tool's answer.

facts.policypolicy facts

type User

fact available(u: User): Int from mcp payments.get_balance() at "available"

call payments.get_balance()
call payments.create_refund(charge: Text, amount: Int)

allow payments.get_balance

deny payments.create_refund
  when amount > available(caller)
  because "more than the balance"

allow payments.create_refund
  when amount > 0

A fact that cannot be found (the tool fails, the path leads nowhere) is unknown, and a condition on an unknown fact fails. An unknown fact never allows a call.

Tests

A policy's tests are in a file of their own, beside it: refunds.tests for refunds.policy. Each test is a call and the decision it must get. given sets facts and state for the test.

first.teststests for refunds

test "a small refund goes ahead"
  when agent calls create_refund(charge: "ch_1", amount: 4200)
  expect allow

test "a big one waits for a person"
  when agent calls create_refund(charge: "ch_2", amount: 30000)
  expect ask "more than 200 €: you decide"

test "a huge one is denied: no rule allows it"
  when agent calls create_refund(charge: "ch_3", amount: 500000)
  expect deny

test "nothing is deleted"
  when agent calls delete_customer(customer: "cus_9")
  expect deny "nothing is deleted from here"
budget.teststests for budget

test "within the day's budget"
  given refunded(agent) = 5000
  when agent calls create_refund(charge: "ch_1", amount: 4200)
  expect allow

test "over the day's budget: asked"
  given refunded(agent) = 15000
  when agent calls create_refund(charge: "ch_2", amount: 15000)
  expect ask "over 200 € refunded today: you decide"

test "too many calls"
  given calls(agent) = 30
  when agent calls list_charges()
  expect deny "too many calls: wait a minute"

In the studio, the tests run as you edit the policy. On your machine, okay-guard check refunds.policy runs them and exits with 1 if one fails, for CI.

Errors

A policy that does not compile is not used; the error says where:

allow create_refund
  when amout <= 20000         8:8: an unknown name amout
ask create_refund
  when charge > 100           11:15: Text > Int: different sorts

Decisions in the journal

Every call is recorded in okay-guard's journal with its decision and why: the rules that applied, the reasons, the facts the decision used (arg:amount(call) = 30000, available(agent) = 1000), and the certificate of the theorem. A denial by default lists the rules that were tried and why each did not apply. Download the journal from the studio's Log, or read it with okay-guard journal on your machine.

Recipes

Only readingallow get_* for each reading tool, nothing else: every other call is denied by default.
Everything but deletingallow * and deny delete_*.
A person for big amountsallow pay when amount <= 100 and ask pay when amount <= 5000: above 5000, denied.
A daily budgeta state … per day and then spent(caller) += amount, as in the budget.
A rate limitdeny * when calls(caller) >= 30 with count * then calls(caller) += 1 and a state per minute.
Files in one placeallow fs.write when path starts "/workspace/" and not (path ends ".env").
One server, its own rulesname the tools with the server: call github.get_file(…), deny github.*.

Reference

policy    ::= "policy" name decl*
decl      ::= type | record | fact | state | call | rule | count
type      ::= "type" Name
record    ::= "type" Name "=" "{" field ("," field)* "}"
fact      ::= "fact" name "(" params ")" (":" sort)? ("from" source)?
source    ::= name | "mcp" [server "."] tool "(" args ")" "at" text
state     ::= "state" name "(" params ")" ":" sort ("per" ("minute" | "hour" | "day"))? "=" literal
call      ::= "call" [server "."] tool "(" params ")"
param     ::= name "?"? ":" sort
rule      ::= ("allow" | "ask" | "deny") target ("when" cond)? ("then" update ("," update)*)? ("because" text)?
count     ::= "count" target ("when" cond)? "then" update ("," update)*
target    ::= tool | server "." tool | server ".*" | "*"
cond      ::= cond "and" cond | cond "or" cond | "not" cond | "(" cond ")" | atom
atom      ::= expr cmp expr | expr "in" "[" exprs "]" | expr ("starts" | "ends" | "contains") expr
            | "has" "(" path ")" | ("every" | "some") name "in" path ":" cond | name "(" exprs ")" | path
cmp       ::= "=" | "!=" | "<" | "<=" | ">" | ">="
expr      ::= expr ("+" | "-") expr | expr "*" literal | "(" expr ")" | literal | path | name "(" exprs ")"
update    ::= name "(" exprs ")" ("=" | "+=" | "-=") expr
sort      ::= "Int" | "Dec" | "Text" | "Bool" | Name | "List" "[" sort "]"

tests     ::= "tests" "for" name test*
test      ::= "test" text ("given" given ("," given)*)? "when" name "calls" tool "(" args ")"
              "expect" ("allow" | "ask" | "deny") text?
given     ::= name "(" exprs ")" ("=" literal)? | "not" name "(" exprs ")"

Names of types start with a capital letter; names of facts, states and arguments with a small one. The variables of a rule are caller, tool and the call's arguments. A tool whose name is not a plain word is written in quotes: call "list-files"(path: Text).

The language is okay-proof's okay-policy: its full specification, the logic underneath and the kernel that checks every decision are there.
